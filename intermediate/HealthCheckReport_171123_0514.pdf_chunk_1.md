This document is a **Cyber Health Check Report** for the domain `raiseforum.org`, generated by the Internet Hygiene Portal (from the Cybersecurity Agency of Singapore) on November 17, 2023.

The report evaluates the website's security posture, assigning an overall score of **79%**, which the report classifies as "**Sufficient**" but notes that the connection is "**insufficiently secured**."

Below are the key insights and facts categorized by security strength and identified vulnerabilities.

### 1. Key Strengths (Security Pass)
The website demonstrates several strong security configurations:
*   **HTTPS Configuration:** The website uses HTTPS and is correctly configured to redirect all HTTP traffic to the secure HTTPS protocol.
*   **Modern TLS Protocols:** The server supports **TLS 1.3** (Strong) and **TLS 1.2** (Sufficient), which are the current industry standards for protecting data in transit.
*   **Cipher Suites:** The server uses secure TLS Cipher Suites with strong security strength.
*   **Protection Against Common Attacks:** 
    *   **Downgrade Attack Prevention:** The server supports `TLS_FALLBACK_SCSV` to prevent attackers from forcing a lower, insecure protocol.
    *   **Secure Renegotiation:** Secure renegotiation is enabled.
    *   **DoS Mitigation:** Client-initiated renegotiation is **disabled**, reducing the risk of Denial of Service (DoS) attacks.
    *   **Compression Security:** Both HTTP and TLS compression are **disabled**, which protects the site from compression-based side-channel attacks (like CRIME).
*   **Certificate Integrity:** The SSL certificate is valid (until Sept 23, 2024), uses a secure RSA public key algorithm, uses a secure SHA-256 hash algorithm, and the domain name matches the certificate subject.

### 2. Critical Vulnerabilities & Weaknesses (Security Fail)
The report identifies several areas where the website is vulnerable to attack:
*   **Lack of HSTS (HTTP Strict Transport Security):** The server is **not** configured with an HSTS policy. This leaves users vulnerable to "downgrade attacks" and "SSL stripping attacks," where an attacker intercepts the connection to force the user onto an unencrypted HTTP connection.
*   **Missing X-Frame-Options Header:** The server does not offer the `X-Frame-Options` header. This makes the website susceptible to **Clickjacking attacks**, where an attacker tricks users into clicking hidden elements on the page.
*   **Session Resumption Risks:** Session resumption is currently **enabled**. While this improves performance, the report notes it opens a window for **Replay Attacks**, where an attacker intercepts and re-transmits valid data transmissions.
*   **No Extended Validation (EV):** The site does not use an EV certificate. While not a direct vulnerability, the report notes that EV certificates provide higher identity assurance to visitors.
*   **Lack of IPv6 Support:** The modern IPv6 protocol support is not available for this connection.

### 3. Summary of Recommendations
To improve the security score and protect users, the report implies the following actions:
1.  **Implement HSTS:** Configure the web server to include the HSTS header with a `max-age` of at least one year and include subdomains.
2.  **Implement X-Frame-Options:** Set the `X-Frame-Options` header to `DENY` or `SAME-ORIGIN` to prevent clickjacking.
3.  **Review Session Resumption:** Disable session resumption if not strictly necessary, or implement advanced security controls like frequent rotation of Session Ticket Encryption Keys.
4.  **Enable IPv6:** Update infrastructure to support modern IPv6 addressing.
