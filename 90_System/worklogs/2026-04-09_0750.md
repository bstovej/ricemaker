# Session Journal: 2026-04-09 07:50

## 🎯 Objective
Investigate why the Ricemaker scheduler appeared to be non-functional, with only a list of pending files showing on the dashboard.

## ✅ Tasks Completed
- **Root Cause Analysis**: Identified that `plan.json` contained "ghost" entries—files marked as `pending` that no longer existed in the physical input directory, causing them to be ignored by the agent but still visible in the UI.
- **UI Enhancement**: Modified `static/js/main.js` to detect missing files, label them as "Missing from Folder", and added a batch cleanup tool.
- **Dashboard Update**: Added a "Clean Ghost Files" button and individual delete actions to `templates/index.html`.
- **Agent Robustness**: Updated `agent.py` with a 10-minute heartbeat log for better observability and added pre-processing existence checks.
- **Verification**: Confirmed the scheduler correctly picks up and processes new files (e.g., `gemini_test.txt`) after the fix.

## 💡 Key Insights & Findings
- **Plan vs. Reality**: In a durable system, the state file (`plan.json`) can easily drift from the actual file system if files are moved/deleted manually. The UI must provide tools to reconcile this drift.
- **Observability**: Long-running background processes (like the agent) need heartbeats to distinguish between "idle/waiting" and "crashed/stuck."
- **Docker Sync**: Confirmed volume mounts for `/Volumes/home/archives/papers` are active and the agent is correctly watching the host filesystem.
