# Session Journal: 2026-04-10 23:45

## 🎯 Objective
Investigate and resolve why files selected for re-review were appearing as "stuck" in a pending state on the dashboard without being processed by the agent.

## ✅ Tasks Completed
- **Root Cause Identification**: 
    - Discovered that `app.py` was failing to move archived files back to the `input_folder` because its `legacy_archive` path was hardcoded to `./reviewed`, which in Docker points to the static image layer rather than the host's actual `reviewed/` folder.
    - Found that `agent.py`'s startup scan completely ignored `pending` entries in `plan.json` if the physical file was missing, leading to "ghost" pending states.
- **Agent Auto-Recovery Implementation**:
    - Enhanced `agent.py` startup logic to cross-reference `plan.json` with the physical filesystem.
    - Added recursive search logic across configured `archive_folder` and the host-mapped `legacy_archive` to automatically find and restore missing pending files.
    - Files not found in any archive are now correctly marked as `error (missing)` instead of staying in the queue.
- **Path Resolution Fix in `app.py`**:
    - Updated the `/api/rereview` endpoint to prioritize searching the host's absolute project path (`/Users/bstove/LocalDocs/projects/ricemaker/reviewed`) which is accessible via the container's volume mount.
- **Deployment & Verification**:
    - Synchronized code changes into the `ricemaker` container via `docker cp`.
    - Restarted the container and verified via `docker logs` that all 5 stuck files were successfully recovered and queued for processing.

## 💡 Key Insights & Findings
- **Container Isolation vs. Host Volumes**: When working with Docker Desktop, hardcoding relative paths like `./reviewed` for persistent storage can lead to "state silos" where the app thinks files are missing because it's looking at the image's filesystem instead of the mounted host volume.
- **Self-Healing State**: Durable agents should not only react to new events but also perform periodic or startup state reconciliation to fix inconsistencies between their database (`plan.json`) and the physical world (filesystem).
